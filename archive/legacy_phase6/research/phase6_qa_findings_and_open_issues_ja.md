# PEAD01｜Phase 6質疑で明確になった仕様と未解決課題

**記録日：2026-11-15／対象：Phase 3・6・6.1。** 研究上の質問をきっかけに、公開実装と集計結果の読み方、今後の検証課題を整理する。**本書は新しいバックテスト結果ではない。**

## 1. 「方式」を二階層に分ける

- **初動計測方法（売買候補側）**：A＝最初の対象セッションの終値まで観測し次営業日寄りで入る。C＝開示後の指定営業日寄りまで観測し、次の寄りで入る。I／P5／B等＝分足や引け前の観測。初動を測る**始点・終点・売買可能時刻**は候補によって異なる。「寄り→引け」一律ではない。
- **パラメータ選択・アンサンブル方式（候補の組み合わせ側）**：Fixed、Single、Top-K、Neighbor、Shrink、Inverse、Parity、Max-Sharpe、Dynamic等。A・CとTop-Kを同じ意味の「方式」と呼ばない。
- Phase 3以降、**初動上昇後ロング**が重要な研究仮説。Phase 6の採用履歴ではロング・20営業日が多い。ただし採用比率は**約定件数・建玉金額・収益寄与率**ではなく、方向別の超過収益を直接証明しない。

## 2. 候補を選ぶまでのWF手順

公開実装 [`phase6_report.py`](../../../src/pead01/phase6_report.py) による。

1. WF更新日を基準に**学習**範囲を定め、学習Sharpeで上位50候補を選択する。
2. 学習と分離した**直近45営業日の内部検証**で、上位50候補をSharpeで再順位付けする。
3. 順位確定後にSingle・Top-K・Neighbor等で候補を決める。
4. **配分ウェイトは内部検証45日ではなく学習範囲の日次リターン系列**から推定する。
5. 更新後の新規注文に採用条件・配分を適用。既存の建玉は従前の出口を維持する。

学習窓：Dynamicは126・252・504営業日または **0＝開始からの拡張窓**。Single、Top-K、Neighbor、通常のShrink、Max-Sharpe等の四半期更新方式は実装上**拡張窓（0）**を使用する。週次（W-FRI）・月次（M）・四半期（Q）は**更新頻度**であって、45日内部検証の長さではない。

**学習と内部検証は重ならない。** 45営業日を252営業日の学習内に含めない。

## 3. アンサンブル方式の意味と相違

| 選択・配分方式 | 候補の選択 | 配分方法 |
| --- | --- | --- |
| Fixed | あらかじめ固定した1条件 | 100% |
| Single | 内部検証1位の1条件 | 100% |
| Top-3/5/10/20/50 | 内部検証順位の上位K件 | 各候補に等ウェイト |
| Neighbor | 内部検証1位の候補と、内部検証候補集合中のパラメータ近傍 | 選ばれた候補に等ウェイト |
| Shrink | 内部検証上位10件 | 学習期間の**50%対角縮小共分散**から非負の配分を算出 |
| Max-Sharpe | 内部検証上位10件 | 学習期間の**平均収益と縮小共分散**を用い、ロングオンリーの戦略配分Sharpeを反復的に近似最大化 |
| Inverse／Parity | 内部検証上位10件 | 逆ボラ／リスク寄与の調整 |
| Dynamic | 学習窓・更新頻度ごとに選ばれる上位10件 | 縮小共分散配分に直近63日DD・直近20日市場騰落などの調整を加える |

**Topの順位は過去のSharpeを使う。** 年率収益の単純な降順ではない。ShrinkはTop-10と候補集合が重なるが、ゼロウェイトもあり、採用候補数とウェイトは異なる。Shrinkが実質Top-2〜3に集中しているかは**配分の実効銘柄数 `1 / Σ(w_i²)`**を各更新期で計算しないと判定できない。損益相関から計算した「実効独立戦略数」とは別概念。

### Neighborの「近傍」の厳密な定義

基準はSingleの1位候補。以下の項目は**完全一致**を要求：`family, direction, universe, condition, sizing, exit_rule, hedge`。

変更を認めるのは4軸のみ：`method`（観測法）、`hold`（保有期間）、`threshold`（初動閾値）、`adv`（流動性）。それぞれコードに固定された並びの**隣接1段階**を距離1とし、4軸の距離合計が1以下の候補を採用する。複数軸を同時に1段階変える候補は入らない。近傍候補は内部検証後の候補集合内に存在する必要がある。該当がなければSingleと同じ1件。**AとCが配列上で隣接することは、経済的に同等の情報時点を保証しない。**

## 4. WFで観測した選択構造と成績

| 方式 | WF Sharpe | 年率収益 | 最大DD | 平均資金稼働率 | 約定 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Single | 2.07 | +1.93% | −0.48% | 2.09% | 58 |
| Neighbor | 1.95 | +1.39% | −0.26% | 1.59% | 63 |
| Top-3 | 0.94 | +1.52% | −1.61% | 4.87% | 334 |
| Top-10 | 0.55 | +0.90% | −1.47% | 8.45% | 1,758 |
| Shrink | 1.24 | +0.58% | −0.23% | 1.49% | 1,296 |
| Max-Sharpe | 1.62 | +1.02% | −0.33% | 3.32% | 1,761 |
| Dynamic_M_252 | 1.68 | +0.61% | −0.20% | 2.27% | 2,857 |

- **候補数を増やしてもSharpeは単調に改善しない。** SingleからTop-3・Top-10への低下は観測した。ただしTop-5・20・50も含めると単調悪化でもない。候補の品質低下・相関・資金競合等の寄与は未分解。
- SingleとNeighborの同一期の候補ID重複率は平均**83.3%**。保有期間・売買方向の設定配分差は**0%**。一方でそれぞれ前期からの候補ID継続率は**0%**。方式間の近さと、時点間の安定性は異なる。
- Top-10とShrinkは同一期の正配分ID重複率**76.7%**でも、共通IDだけでウェイトを再正規化した配分差は平均**61.4%**。**何を選ぶかと、いくら配分するか**を分けて研究する必要がある。
- **高Sharpeでも低稼働・少数約定**のため元本全体の年率収益は低い。WFは既観測期間の擬似OOSで、研究から独立した未観測OOSではない。

## 5. Dynamicの12設定とばらつき

Dynamicでは、`Dynamic_{更新頻度}_{学習窓}` の名称を使う。例えば `Dynamic_M_252` は**月次更新・学習252営業日・内部検証45営業日**。学習窓`0`は学習ゼロではなく、利用可能な過去全期間を使う拡張窓。

| 学習窓 | 週次Sharpe | 月次Sharpe | 四半期Sharpe |
| --- | ---: | ---: | ---: |
| 126営業日 | −0.46 | −0.40 | +0.05 |
| 252営業日 | +1.41 | +1.68 | −0.03 |
| 504営業日 | +1.53 | −0.21 | +1.50 |
| 拡張窓（0） | +0.82 | −0.48 | +1.23 |

- **同じ252日でも月次1.68・四半期−0.03**と開きがある。学習窓・更新頻度の優劣をこのデータだけで確定できない。
- Dynamic_M_252は**17回更新**、Top-10は**6回更新**。更新頻度の差と1回あたりの採用条件の変化は区別する。
- WF評価は**334営業日程度**。四半期は6期間のみ。12方式から最良を事後選択すると、方式の選択自体に**勝者の呪い**が発生する。
- 詳細は[アンサンブル方式横断の採用パラメータ比較](../reports/phase6_ensemble_parameter_comparison.md)および[Top-10の各期採用履歴](../reports/phase6_top10_wf_parameters.md)。

## 6. 最大120営業日に由来する学習・検証ブランク

実装上、`cap = max(daily_holds) + 4 = 124`。WF更新日の位置を`start`としたとき、境界インデックスは以下。

```text
train_end = val_start - cap - 5  # 学習終端
val_start = val_end - 45        # 45営業日内部検証の開始
val_end   = start - 5           # WF開始前の5営業日を空ける
```

したがって**学習と内部検証の間は約129営業日の間隔**、内部検証と次の更新適用の間は5営業日。学習終端からWF開始までは概ね**129 + 45 + 5 = 179営業日**離れる。これは**学習期間の長さ（126／252／504）とは別の時間差**である。

**研究仮説：** 保有20日など比較的短い候補にも、最長保有120日＋再試行を前提とした一律ブランクを課しているため、学習データの鮮度が落ち、Dynamicの条件選択が不安定化している可能性がある。**原因と断定できず、現在の結果から効果量は不明。**

**60営業日案：** 最大保有を60日とする評価は感応度分析の候補。ただし、120日・90日の候補を残して単純にブランクを縮めると、期間境界をまたぐ損益によるリークのおそれがある。比較には (a) 60日超保有候補の除外、または (b) 実際のシグナル時刻・決済時刻に応じた候補／取引単位のpurging・embargoが必要。**リーク回避とデータ鮮度を両立する設計**を優先する。

## 7. 優先度付きの未解決課題

1. **ブランクの感応度とリーク点検：** 現行120日基準、最大60日基準、候補別の保有終了時点に基づくpurgingを比較。学習・検証・WF境界を跨ぐラベルの利用がないかテストする。これは未実施。
2. **既存ファイル再利用の可否：** 保存済み候補の損益系列・価格経路を流用し、**候補ランキングとWF再生のみ**を再計算できるか調査。保有上限・候補集合を変えるなら比較母集団を揃える。実際の計算量・Codexトークン負荷は事前に測る。
3. **Dynamicの機構別寄与：** 「候補の更新のみ」「学習期間の共分散縮小配分を追加」「DD・市場環境補正を追加」を同じWF評価窓・コストでアブレーションする。
4. **Top-K→Shrinkの配分集中：** 各更新期で`1/Σ(w²)`・最大ウェイト・上位2／3条件のウェイト合計を出し、Shrinkが実質Top-2〜3か検証する。採用頻度と**実際の約定・建玉重複**も照合する。
5. **方式間の分散効果：** Single・Neighbor・Dynamic・Shrinkの実際の日次損益相関、同時損失、ポジション重複、機会費用を比較する。候補IDの非重複だけで収益分散効果を主張しない。
6. **独立OOS：** 最終的な選択手順は事前固定し、既観測期間で最良だった方式を後追いで「独立OOSの勝者」と扱わない。

**研究判断：** 既存データが短い段階では、12種類のDynamicから一つを最良と断定せず、ブランク設計や選択・配分の分解を先に行う。高コストの全件探索再実行は必要性を検証してから着手する。
