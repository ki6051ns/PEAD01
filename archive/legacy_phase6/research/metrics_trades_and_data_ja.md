# PEAD01｜指標の読み方・取引評価・使用データ

**2026年11月14日時点の説明資料。** Phase 6.1の集約結果を基に記載。取引明細とデータ取得コードをまだ照合していない項目は「未確認」と明記する。

## 1. 研究は何を狙っているか

決算発表直後の株価の初動を観測し、その後に価格の継続（ドリフト）や反転が起こるという仮説を検証する。売買条件は決算イベント、シグナルの向きと強さ、エントリー時刻、保有期間、流動性など。初動を観測する前の価格で約定できたと仮定してはいけない。

## 2. WFとは

**WF（Walk-Forward、ウォークフォワード）**は、過去の学習期間で戦略条件を選び、その後の評価期間で成績を測定し、期間をずらしながら繰り返す手法。**IS**は学習期間内。**固定グリッド事後評価**は研究者が結果を観察した後に候補を選べる集計。**独立OOS**は戦略を固定するまで一切見ていなかったデータでの検証。PEAD01の報告済みWFは研究過程で観察した期間を含み、独立OOSではない。

## 3. 数字の意味（初期資本1億円）

- **年率収益1.88%**：年率換算で元本1億円に対し約188万円に相当。実際に毎年188万円が確定するという意味ではない。
- **Sharpe 2.02**：平均日次収益を日次収益の標準偏差で割り年率換算するリスク調整指標。現金収益率の扱いなど計算仕様は実装で要確認。
- **最大DD −0.49%**：評価期間の資産価値が直前ピークから最大0.49%下落。1億円を基準にした約49万円は概算であり、実際の最大下落額と完全一致するとは限らない。
- **平均稼働率2.10%**：平均建玉が初期資本比約2.10%に相当。1億円なら平均約210万円の建玉。最大建玉は別指標。
- **WF約定58件**：取引記録上の約定数。これが58個の独立した勝敗イベントかどうかは取引明細の定義次第。
- **日次勝率**：評価対象営業日のうち日次損益がプラスだった日数の割合。ポジションを持たない日が含まれる可能性があるため、取引勝率ではない。
- **プラス月率**：月次損益がプラスとなった月数の割合。月ごとの利益額の大小は反映しない。

## 5. 成功した取引・失敗した取引

**個別取引の銘柄、決算日、約定時刻、売買理由、損益、事前に狙った価格方向は、現在の公開集約表だけでは特定できない。** 集約表の `win` を「58取引のうち何件勝ったか」と解釈することはできない。

今後、取引明細（ライセンス対象の元データは公開せず、公開可能な派生情報のみ）から次を算出する。

| 分析項目 | 定義・確認内容 |
| --- | --- |
| 取引勝率 | 費用控除後の確定損益がプラスとなった完了取引数 ÷ 完了取引数 |
| 方向的中率 | 事前に想定した上昇・下落方向と実現リターンの符号が一致した取引の割合 |
| 平均勝ち／平均負け | 利益取引の平均利益額・損失取引の平均損失額 |
| プロフィットファクター | 総利益 ÷ 総損失の絶対額 |
| 代表的な成功例 | 決算情報、観測できた初動、注文時刻、保有期間、費用控除後損益を時系列で説明 |
| 代表的な失敗例 | 反転、ギャップ、遅延、業種要因、流動性不足、費用負けなどを実際の記録に基づいて分類 |
| 狙いどおりか | 仮説で想定した時間帯・方向の収益か、市場全体の上昇や保有期間延長による収益かを分解 |

「想定した方向へ動いたが費用負けした取引」と「想定方向と逆に動いた取引」は別に集計する。

## 6. 使用データと現状の確認範囲

**これまでの研究説明から確認できる範囲**

- **日本株の決算・業績関連情報**：決算発表イベント、業績予想修正等（J-Quantsを利用した研究環境）。
- **日本株の株価データ**：日足OHLCV、分足の価格・売買情報を利用した分析。
- **銘柄属性**：業種、時価総額、流動性、TOPIX対象銘柄等の区分・条件。
- **派生データ**：初動リターン、将来ホライゾン別リターン、シグナル、ポジション、費用、日次NAV、WF集計。
- **研究期間**：概ね2021年11月〜2026年11月13日。分足の検証では主に2024年11月〜2026年11月を使用。

**未確認であり、取得コード・マニフェスト照合が必要な項目**

- 正確なJ-Quants APIエンドポイント、商品プラン、データバージョン、取得日。
- 使用した決算発表時刻・業績予想修正の原データ列と、利用可能時刻の定義。
- 分足の配信元・補正方法・タイムゾーン・欠損処理。
- 業種分類・TOPIX構成銘柄の時点整合性、上場廃止銘柄の取り扱い。
- 取引別の勝敗・方向的中率、期間別の売買件数、注文容量・スリッページの実測。

## 7. 次の検証

新規の大規模探索ではなく、既存コードと約定台帳を確認し、取引単位の勝率・方向的中率、成功・失敗の代表例、データ出所一覧を作成する。その後、信用規制・約定容量・独立OOSを検証する。
