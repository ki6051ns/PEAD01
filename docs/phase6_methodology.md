# Phase 6 方法と再開

```powershell
$env:PYTHONPATH = "src"
$env:OPENBLAS_NUM_THREADS = "2"
.venv/Scripts/python -m pead01.phase6 --output data/phase6_v6
.venv/Scripts/python -m pytest -q
```

`phase6.json` は固定候補・容量・更新周期を定義する。データと設定のSHA-256が一致する保存先では、保存済みの価格経路と方式・保有期間別スクリーニングを再利用する。大規模な計算は単一プロセスで、NumPy集約と圧縮チェックポイントを使用する。Phase 1〜5のデータを読み取る。

## 二段階探索

対象はA（初動方向）、B（修正・実績情報）、C（逆方向）、D（複数時間軸と出口・配分）、E（属性・レジーム）。初動閾値、流動性、TOPIX所属、方向は主格子。業種・財務・その他の詳細軸は3・20日、60分、引け、Phase 5短期出口に絞る。分足は初回約定から5・15・30・60分の観測を使い、その次の指定分の正の出来高の始値を条件とする。休日、休止、未約定を持ち越さない。日次はPhase 3のA・Cと引け前・分足由来の観測時刻を維持する。日次出口は1〜120営業日。ストップ・トレーリング・失速・反転は日足引けで判定し、翌朝始値の約定が観測できるときに前倒しする。

第一次スクリーニングはスパースな価格経路を合成し、グロスが1を超える日は比例制限する。日中の注文順・同銘柄重複を処理する共通台帳は、上位20条件、固定ルール、各アンサンブルに適用する。したがって一次最高と制約付き上位20件の最高は異なる母集団の結果。40件未満の一次候補は順位付けから除くが、カタログに保存する。財務情報の即時取得は未確認のため理論上限。集中度は発表前営業日の既知件数を代理とする。

## 共通台帳

1億円、銘柄最大100万円、事前売買代金1%。同時刻・同銘柄の注文需要を符号付きで合計し、相殺する。一致する方向の最大配分の候補が出口を代表する。同一銘柄の保有中に届く注文はスキップする。約定容量は事前売買代金を使う。S/LSは貸借区分を適用。日次往復20bp、分足10bp、持越し借株年1%。ベータヘッジはTOPIXによる価格近似。実際の板、受注、ロット、費用、先物のベーシス、借株の確約は未確認。

## Walk-forward

2025年7月以降を共通評価区間とし、過去の候補損益から学習、45営業日の内部検証、次期評価の順。境界では最大保有120営業日と再試行4日を使って学習・検証間を保守的に空け、評価前にも5日を空ける。選択と重みは予定更新日までのデータのみ。重み変更は新規注文に適用し、既存ポジションは予定の出口を使う。動的方式は週・月・四半期と126/252/504日・拡張窓の全12案。Top-K、近傍、縮小共分散、逆ボラ、リスクパリティ、最大Sharpeを比較する。共分散縮小は対角50%を事前固定。

評価時系列はすべて2026年11月13日以前の観測済み資料による擬似OOS。将来のスナップショットを別の `--data` と `--output` で指定し `--forward-only` を使うと、固定4ルールのカットオフ後に開示したイベントだけで再生できる。上流のイベント・バー・シグナル更新が必要。現在のスナップショットでは独立OOSは空。

実効独立数は相関固有値の参加率。重なりは銘柄・日付・方向、またはイベントIDのJaccard。損失側最悪1%日での他候補の負損益比率を下方依存とする。証券会社の当日受注条件や実際の借株条件は未観測。未決済の銘柄は最後の観測値で評価し、仮の決済を作らない。財務情報による当日中の選別は探索の約定候補から外す。
